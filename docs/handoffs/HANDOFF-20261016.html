Status on 16 October

  • Strongest model in head-to-head play: D028 (absolute seats). It beat D027 0.380 [0.338, 0.423] at guidance 0.10. D027 beat D025 0.406 after uct_c 1.0 and policy-target pruning sharpened the search targets.
  • Seat 2's collapse was learned, not a property of the game. Under every rule change tried, seat 2 won about 2% of network-guided games; with the heuristic alone it won its share. The network's input and value outputs are per absolute seat, so it learned separate play per seat, and seat 2 fell into a loop where its positions taught nothing (section 3).

But D030 is much weaker than D028: 0.105 against it. The runs started from D028 in a view where its search falls apart, and spent ~21,000 games climbing out (section 4).
  • Next run, D031: a self-play teacher. D028, searched with its own seat shown as player 0 (which plays every seat well), plays the self-play games; a mover-relative network learns from them (ini selfplay_teacher_weights, section 6).
  • Fixed: the laptop never received guidance_blend_normalized (D021–D029), so it played with about half heuristic instead of the configured 10%. The desktop now sends every simple setting, and the laptop prints the important ones at startup.

2. Sharper search targets

  • Guidance doesn't control target sharpness. search_sharpness.py on D023: visit entropy 91 / 90 / 90 / 87% of uniform at guidance 0 / 0.10 / 0.38 / 1.0. The heuristic alone is barely sharper than the network (prior 89% vs 95%).
  • uct_c does. At guidance 0.10: uct_c 2.0 / 1.0 / 0.5 / 0.25 gives 90 / 86 / 79 / 70%. The median Q gap between moves is only ~0.02, so the exploration term dominates at 2.0.
  • uct_c 1.0 plays as well as 2.0 (D024 against itself: 0.335), so it became the default (ini uct_c).
  • Policy-target pruning (KataGo) did nothing in its standard form: plain PUCT is already in balance, so 99% of visits counted as earned. Judged against the prior before Dirichlet noise it removes the noise-only visits: ~96% kept, target entropy 91 → 89% (uct_c 2.0) and 87 → 85% (1.0).
  • Together (D027): target H fell from ~1.57 to 1.43 within the run; D028 continued to 1.27. D027 beat D025 0.406, the third-largest gain in the project.
  • The value probe gained a balanced score (top-pick averaged over seats). Plain top-pick rewards backing the seat that usually wins: D027 rated seat 0 best in 82% of v2 positions and beat D028 on top-pick, while D028 was level or better on balanced.

  • Log analysis (D025): seat 2 kept pace for ~8 turns, then fell 4–5 of its own turns behind by its second route; its share of centers built in cities was 43% against 70% for seat 0. Starting goods help only a little (17% with a huge head start), and turn order or end timing not at all.
  • The heuristic alone is fair, so the mechanics are symmetric enough. The observation layout, value outputs and value targets were checked: all symmetric by seat.
  • The relabel test settled it. Shown seat-2 positions as player 0 (one fixed relabel per search), unchanged D028 won 24% from seat 2 instead of 1.6%. The network can play the game; it never learned to play it as player 2. It also plays seat 1 better natively (58%) than with its seat-0 skill (35%): separate skills per seat.
  • Cause: the observation has per-seat plane blocks and seat-to-move planes, and the value head outputs per seat. Once seat 2 fell behind, its positions' values were all ~−0.7, its search targets carried no information, and its play stopped improving while seats 0 and 1 kept learning.
  • The rule options built for this (starting_*_goods_by_seat, end_game_finish_round, main_play_start_seat) stay available, off. Revisit them only after a seat-neutral network shows a real imbalance.

4. Mover-relative training

  • What it is (ini mover_relative_obs): every position is shown from its player to move's point of view: that player in slot 0, the next player in slot 1, the one after in slot 2 (turn order kept), with value outputs in the same slots. Search, stored positions, training targets (value and route) and the actors' value checks all use it. Positions where player 0 moves are unchanged. One skill serves every seat, and every game trains it from all three viewpoints.
  • It works for balance: D029–D030 self-play seats 33.5 / 32.6 / 33.8% over 16,000 games; seat 2 takes a full share of both win types.
  • It cost strength, because of the starting point. D029 began from D028's weights. Searched per position, D028's seat-specific value head reads the searching player from a different slot at different nodes, and the search falls apart (the first relabel test: 11 of 476 games). So D029's self-play started near 2% strength, and D030 had climbed only to 10.5% against D028 (12 / 30 / 9 of 167 from seats 0 / 1 / 2).
  • Self-play under mover-relative training was also less decisive: ~54% natural wins and ~410-move games, against D028's 91% and ~233.
  • D030 was trained correctly (checked): stored positions all have the seat-to-move marker in slot 0, and each slot's score correlates with the same slot's value target. D030 scores about the same on the value probe in either view (60.5 vs 59.4% balanced) because it learned to ignore the now-constant seat marker and judge each slot by its own data.
  • The v2 value probe is biased against mover-relative models: its positions come from D028 vs D027 games, where seat 2 finishes best in 2.5% of positions. A fair probe needs positions from games involving the new models (record a v3 set).

6. The plan: D031 with a teacher

  1. How the teacher run works

    • selfplay_teacher_weights = mali_ba_agent_vD028.weights.h5 (already set). The trainer loads D028, publishes its weights to the actors once and never sends its own; it still trains and saves the network given by --load_model_path.
    • Actors search with D028, with the searching player's seat shown as player 0 for the whole search (the mode that won 45 / 35 / 24% from seats 0 / 1 / 2 against D028). Positions are stored mover-relative, which at the root is exactly the teacher's frame, so the trainer side is unchanged.
    • Remote workers get the setting and the teacher's weights with every job. The startup printout says self-play network : fixed teacher …; the main log no longer shows "Learner updated to latest weights" (nothing is sent).
    • Smoke test: 8 teacher games, all natural wins at 152–369 moves; the trainer trained and saved weights that moved from its starting point, not the teacher's.

  2. Starting D031

    • Network to train: D028's weights are the better start. In the stored mover-relative frame, D028's outputs at the root are the teacher's own (its seat-0 skill), so it starts matched to its targets; its seat-specific value bias gets trained out by symmetric data. D030 is the alternative (already seat-neutral but much weaker).
    • Buffer: start empty; D030's buffer holds weak self-play games. Rename it (e.g. mali_ba_buffer.D030-weak.pkl.gz); min_buffer_to_train = 10000 waits ~30 minutes.
    • Desktop and laptop can both run: the laptop gets the teacher with its jobs. Rsync train_mali_ba.py, training_utils.py, remote_actors.py, mali_ba.ini first and check its printout.
    • Interval: 10 s desktop-only, 8 s with the laptop.

  3. What to watch, and afterwards

    • Self-play should look like D028's: decisive (most games natural wins, ~200–300 moves), seats roughly even (teacher play with the relabel is much closer to fair than plain D028).
    • Training metrics: POLICY FIT gap falling (the network learning the teacher's targets), value calibration.
    • After the run: D031 (mover-relative) vs D028 and vs D030, and record a v3 probe set from one of them. If D031 is close to D028, set selfplay_teacher_weights back to empty and continue with normal self-play from D031.

  4. Still open

    • Make the normalized blend the evaluator's default; policy_probe.py still uses the old blend (TODO).
    • Training interval with the laptop (8 s) vs desktop only (10 s); fast budget 40 → 80; FPU for big route decisions; Gumbel targets (TODO).
    • The desktop's memory tests are still not done; no memory errors since 11 October.

9. Things that misled us (don't repeat)

  • ab_eval's progress line counts agents, not seats. [A 167 B 172 C 149 …] with the same model in all three seats is always near a third each. Seat shares are in the "wins by seat" line and the seat_balance summary. We briefly read "34 / 35 / 30%" as a seat fix that wasn't there.
  • A setting the desktop didn't send fell back silently on the laptop. The laptop played D021–D029 with the old guidance blend (~half heuristic): its self-play won 62% vs 29% (D029), 99% vs 92% (D027). Check the laptop's startup printout against the desktop's every run.
  • Per-position relabelling of an absolute-seat network breaks its search (the searching player sits in different slots at different nodes). Relabel once per search for diagnostics; train mover-relative networks per position.
  • Starting a new input view from an old network's weights isn't a warm start if the old network searches badly in that view: its self-play games teach little. Use a teacher that plays well (D031).
  • Plain value-probe top-pick rewards seat priors. Use balanced, with the seat picks; and probe with positions from games like the ones the model plays.
  • Seat balance depends on the model and its strength, not only the rules. It looked fair in near-random play and collapsed as play improved; seat 0 vs 1 flipped between models.
  • Overwriting a probe file: --record_positions to an existing name replaces it (v2 now holds the guidance-0.10 game's positions). Use a new name each time.
